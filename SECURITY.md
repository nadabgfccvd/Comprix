# Security Policy

## Scope

Comprix is a **100% offline** Android app: the release APK requests **no `INTERNET` permission** (verified in CI/QA), has no accounts, no cloud, no telemetry, and stores all data in a local Room database.

## Supported versions

| Version | Supported |
|---|---|
| 1.4.2 (latest) | ✅ |
| ≤ 1.4.1 | ❌ legacy — signed with the retired key; upgrade recommended |

## Reporting a vulnerability

Please report privately via [GitHub Security Advisories](https://github.com/nadabgfccvd/Comprix/security/advisories/new). Do not open a public issue for security problems. You can also reach the maintainer through the repository owner profile.

## Signing key rotation (2026-10, v1.4.2)

Releases up to **v1.4.1** were signed with a keystore that was auto-generated by the build script and committed to this repository with a fixed passphrase (`keystore/comprix-release.jks`, store/key password hardcoded in `app/build.gradle.kts`). That key is therefore **considered compromised**: anyone could have built an APK signed with the same identity.

Actions taken:

1. The old key is **retired** — it must never sign a production build again.
2. The keystore file, the backup archives that contained it, and the hardcoded passwords were removed from the repository **and from the entire git history** (history rewrite + force push; tags were re-pointed to the rewritten commits).
3. A new **4096-bit RSA** keystore was generated and kept **outside** the repository. Signing credentials are loaded from a gitignored `keystore.properties` (see `app/build.gradle.kts`); without it, `assembleRelease` produces an unsigned APK.
4. **v1.4.2** is the first release signed with the new key. Android blocks direct updates across a signing-identity change, so users migrating from ≤ v1.4.1 must **uninstall → install**; the in-app local **backup/restore** covers the data. Details: [`docs/ROTACAO-DE-CHAVE-v1.4.2.md`](docs/ROTACAO-DE-CHAVE-v1.4.2.md) (pt-BR).
5. APKs already published for ≤ v1.4.1 remain downloadable as historical artifacts. If you trust only the new identity, verify the signer certificate of any APK before installing (`apksigner verify --print-certs`).

## OCR & allergen data

Label recognition (ML Kit OCR) and allergen detection (text rules, RDC 26/2015) are **suggestions**. Confidence values shown by the app are heuristic weights per field, not calibrated probabilities. Results can be wrong in both directions; every extraction goes through a manual review screen, and the physical label always prevails.
